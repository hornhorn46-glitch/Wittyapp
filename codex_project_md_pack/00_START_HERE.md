# Codex Project Operating Pack — Start Here

This folder defines how Codex must work on this project.

The goal is not to produce a quick prototype that merely launches. The goal is to reach a clearly defined playable milestone with tested logic, acceptable visuals, working content, and a concise final report.

## Priority order

1. Obey the user's concrete task exactly.
2. Preserve and improve the existing project structure before inventing a new one.
3. Ask only the necessary clarification questions at the intake stage.
4. After the milestone is agreed or inferable, work autonomously until completion.
5. Keep long-term working context in Markdown files, not in chat memory.
6. Validate with automated tests, smoke runs, and at least one playthrough/simulation of the actual game loop.
7. Do not call unfinished placeholders a finished feature.

## Non-negotiable rule

If the user gives a specific task such as `find open assets on the internet`, `make a real menu`, `add tests`, `make 5 distinct levels`, or `fix visual artifacts`, do not replace it with a cheaper alternative unless the task is objectively impossible in the current environment. If impossible, document why and produce the closest safe fallback plus a clear follow-up checklist.
